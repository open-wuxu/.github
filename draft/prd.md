

一、定义工业软件系列的愿景

1. 核心定位
品牌定位：

Visual Software for the Physical World

面向物理世界的可视化专业软件。

中文愿景：
让物理世界变得可见、可知、可模拟。

通过开放的软件技术和直观的可视化交互，降低工业数字化、设备管理与仿真分析的技术门槛，让每个专业领域都能拥有轻量、开放、可自主掌控的数字化工具。

这里有一个重要区别：

传统工业软件通常围绕生产管理、设备控制或工业自动化构建。

而这个品牌可以围绕三个核心能力构建：
Physical World
现实物理世界

Observe

感知与观测

Understand

建模与理解

Simulate

模拟与推演

Digital Representation

数字化映射、可视化、分析与决策


三个能力分别对应：
能力	主要问题	产品方向
Observe	现在发生了什么？	设备监控、IoT、资产管理
Understand	为什么会这样？	数据分析、设备关系、故障诊断
Simulate	如果这样做会怎样？	数字孪生、仿真、预测

这套理念比单纯的工业物联网定位更有延展性。

2. 品牌应该坚持的四个原则
- Visual First：可视化不是附属功能，而是产品的主要交互方式。
- Open Source：核心能力开源，鼓励开发者和行业用户参与。
- Self-hosted：支持本地部署、私有化部署、离线运行。
- Domain Focused：专注垂直领域，不做大而全的工业平台。
- 
尤其是最后一点。

不建议开发一个试图同时管理工厂、设备、生产线、能源、仓储、物流的超级平台。

应该通过一个个独立产品解决明确的问题。

二、品牌命名：

WUXU · 物序
Engineering the Physical World

品牌理念：让万物有序，让复杂可见。

「物」代表设备、设施、空间、物理实体；「序」代表结构、关系、状态、运行规律。

特点：
- 中文辨识度较好。
- 不被 IoT 或数字孪生限制。
- 能覆盖设备管理、工业建模、仿真和工程软件。
- 有专业、理性、工程化的气质。

三、产品矩阵规划（暂定）

采用独立产品组合，而不是一个大平台内的多个功能菜单。

整个产品体系划分成四个系列。
1. 产品系列

01 · Asset
首批切入
设备与资产管理
- 设备建模
- 设备台账
- 设备状态监控
- 传感器数据
- 设备拓扑关系
解决：设备在哪里、是什么状态、如何管理。

02 · Twin

数字孪生
- 设备数字模型
- 3D 场景建模
- 实时数据映射
- 设备关系映射
- 场景交互
解决：如何让真实设备拥有可交互的数字映射。

03 · Sim

仿真与模拟
- 设备运行仿真
- 工艺流程模拟
- 资源调度模拟
- 离散事件仿真
- 场景推演
解决：不同条件下，系统将会如何运行。

04 · Insight

工业数据分析
- 时序数据分析
- 设备运行分析
- 异常检测
- 能耗分析
- 运行趋势
解决：如何从大量工业数据中发现有价值的信息。


这里的 Asset、Twin、Sim、Insight 是产品系列名称建议，不是必须采用的最终名称。

2. 产品之间的关系
这四个系列不是完全独立的，它们有天然的技术关联：
Asset · 设备与资产

设备实体、属性、关系、实时状态

Twin · 数字孪生

设备模型、空间模型、实时映射


Sim · 仿真

运行模拟与推演

Insight · 分析

运行分析与洞察


例如，一个工厂设备管理场景：
- Asset 管理设备、传感器和设备关系。
- Twin 展示设备在工厂空间中的数字映射。
- Sim 模拟设备运行及生产流程。
- Insight 分析设备的历史运行数据和异常。
这就形成了一个有实际业务逻辑的产品矩阵。

但初期不应该同时开发这四个产品。

四、第一个产品：计划从轻量级工业 IoT 平台切入

一个可视化、可扩展、自主部署的轻量级设备管理与监控系统。

暂时可以叫 Asset Studio。

1. MVP 功能设计

模块	MVP 功能	优先级
设备管理	设备注册、编辑、分组、标签	P0
数据接入	MQTT、HTTP API	P0
实时监控	设备状态、传感器数据	P0
可视化	仪表盘、时序图、状态卡片	P0
设备拓扑	设备关系、层级结构	P1
告警管理	阈值告警、事件记录	P1
数字孪生	设备模型、简单场景映射	P2
仿真	简单规则模拟、数据回放	P2

第一版就有一个比较有辨识度的能力：

Visual Asset Map：设备可视化地图。

用户可以通过画布创建设备、设备组、传感器及其连接关系，直接观察整个系统的运行状态。

这样产品不会只是又一个设备数据看板。

2. 技术架构
建议优先考虑模块化单体架构：
                  Web Application
                         |
                  REST API / WS
                         |
                 Go Backend Core
                         |
       +-----------------+----------------+
       |                 |                |
   Asset Domain      Data Engine      Rule Engine
       |                 |                |
   Device Model      MQTT/HTTP       Alert / Event
       |                 |
       +-----------------+----------------+
                         |
                   Data Storage
                         |
              PostgreSQL / Time Series


技术栈：
层级	技术
前端	React + TypeScript
可视化	React Flow / ECharts
3D	Three.js
后端	Go
消息接入	Eclipse Mosquitto / MQTT
数据库	PostgreSQL + TimescaleDB（可选）
消息处理	内部事件机制，后续按需引入 NATS
部署	Docker Compose
监控	Prometheus + OpenTelemetry

注意：第一版不需要引入 Kubernetes、Kafka、复杂微服务，也不需要自研 MQTT Broker。
先把设备模型、数据接入、状态展示、可视化交互做扎实。

六、品牌和产品的视觉体系

而工业软件品牌建议采用：
- 工程感。
- 空间感。
- 几何结构。
- 精确、理性。
- 低饱和、克制的配色。
- 强调信息层次和状态反馈。


这里的状态色应该由实际设备状态驱动，而不是简单作为装饰。
